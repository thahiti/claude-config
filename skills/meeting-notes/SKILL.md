# Meeting Notes

## Overview

회의록은 나중에 읽는 사람이 두 가지를 빨리 찾기 위한 문서다. 무엇이 정해졌는가와
내가 뭘 해야 하는가다. 대화 순서를 그대로 옮기면 둘 다 찾기 어려워진다.

## 구조

볼드 섹션 제목과 계층형 불릿으로 구성한다. 액션 아이템은 담당자와 함께 별도 섹션으로 뺀다.

```markdown
**일시** 2026-08-24 14:00 ~ 15:00
**참석** 홍길동, 김철수, 이영희

**논의 사항**

- 검색 응답 지연
  - 현재 p95 가 1.8초로 목표 800ms 를 넘음
  - 원인은 인덱스 갱신과 조회가 같은 커넥션 풀을 쓰기 때문으로 파악
  - 풀 분리와 캐시 도입 두 안을 비교, 풀 분리를 먼저 적용하기로 함

- 다음 스프린트 범위
  - 결제 연동은 외부 일정에 묶여 있어 이번 스프린트에서 제외

**결정 사항**

- 커넥션 풀을 조회용과 갱신용으로 분리한다
- 결제 연동은 다음 스프린트로 미룬다

**액션 아이템**

| 담당 | 할 일 | 기한 |
|---|---|---|
| 김철수 | 커넥션 풀 분리 적용 후 p95 재측정 | 8/28 |
| 이영희 | 결제 연동 일정 외부 확인 | 8/26 |

**보류**

- 캐시 도입은 풀 분리 결과를 보고 다시 판단
```

## 작성 규칙

- 발언자별로 적지 않는다. 주제별로 묶고 그 안에서 논점, 근거, 결론 순으로 계층을 만든다.
  누가 말했는지는 책임 소재가 걸릴 때만 남긴다.
- 결정 사항과 논의 사항을 섞지 않는다. 논의 중에 나온 의견을 결정으로 올리면
  나중에 합의되지 않은 내용이 확정된 것처럼 읽힌다.
- 액션 아이템에는 담당자를 반드시 적는다. 담당이 정해지지 않았으면 그 사실을 적는다.
  담당 없는 항목은 아무도 하지 않는다.
- 결론이 나지 않은 논점은 지우지 말고 **보류** 로 남긴다. 다음 회의에서 같은 논의를
  처음부터 반복하지 않게 하는 장치다.
- 회의에서 나오지 않은 내용을 추론해 채우지 않는다. 맥락이 비면 비었다고 적는다.

## Common Mistakes

| 실수 | 왜 문제인가 |
|---|---|
| 발언 순서대로 받아적기 | 읽는 사람이 결정 사항을 스스로 찾아야 한다 |
| 액션 아이템을 논의 사항 안에 섞기 | 자기 할 일을 놓친다. 별도 섹션으로 빼는 이유다 |
| 담당자 없는 액션 아이템 | 실행되지 않는다 |
| 보류 항목 생략 | 다음 회의에서 같은 논의를 반복한다 |
| 빈 맥락을 추측으로 채움 | 회의록이 사실 기록이 아니게 된다 |
