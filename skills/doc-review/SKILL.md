# Doc Review

## Overview

이미 있는 문서를 다듬는 작업이다. 새로 쓰는 것이 아니라 원문을 고치는 것이므로,
기본값은 "그대로 둔다" 이고 고치는 쪽에 근거가 필요하다.

가장 중요한 제약은 **글쓴이의 목소리가 남아야 한다** 는 점이다. 다듬은 뒤에도 같은 사람이
쓴 글로 읽혀야 하고, 다른 사람이 손댔거나 AI 가 썼다는 티가 나면 실패다.

## 유지할 것

- 말투와 어미. `~합니다`, `~해요`, `~한다` 중 원문이 쓰는 것을 그대로 쓴다.
  문장 하나만 어미를 바꿔도 그 문장이 튄다.
- 글쓴이가 즐겨 쓰는 표현과 문장 길이의 리듬.
- 문단 순서와 논지 전개. 구조 재배치는 논리가 실제로 끊긴 경우에만 한다.

## 고칠 것

| 대상 | 처리 | 예 |
|---|---|---|
| 과장, 최상급 | 사실 수준으로 낮춘다 | 초과 달성 → 달성, 가장 높게 → 높게 |
| 거창한 포장 | 담백하게 줄인다 | 조직의 핵심적인 역할 → 충분히 역할 |
| 지나친 문어체 | 실제로 쓰는 말로 | 당부드립니다 → 해주시면 좋겠습니다 |
| 어색한 단어와 조사 | 자연스러운 표현으로 | 직역 투를 한국에서 쓰는 말로 |
| 기계적 나열 접속사 | 문단 구분으로 대체 | 또한, 그리고, 아울러 의 반복을 끊는다 |

실무에서 굳어진 외래어는 그대로 둔다. 얼라인, 피드백, 싱크, 디플로이 같은 말을
억지로 한국어로 옮기면 오히려 어색해지고 글쓴이의 말투에서도 멀어진다.

전체 톤은 고급스럽고 업무적으로 formal 한 쪽으로 맞춘다. 다만 이는 어휘 선택의 문제이지
어미를 바꾸라는 뜻이 아니다.

## 접속사를 문단 구분으로 바꾼다는 것

"또한", "그리고", "아울러" 가 문단마다 반복되면 항목을 이어 붙인 목록처럼 읽힌다.
접속사를 지우고 문단을 나누면 각 문단이 하나의 논점을 가진 단위로 서고, 독자가
어디서 논점이 바뀌는지 알아본다. 접속사를 지운 자리에 다른 접속사를 넣지 않는다.

## 피드백 문서

인사 평가나 동료 피드백처럼 사람에 대해 쓰는 문서는 마지막을 짧은 개인적 조언
한 문장으로 닫는다. 앞의 평가를 요약하지 말고, 다음에 무엇을 해보면 좋을지를
한 문장으로 건넨다.

## 결과 제시

다듬은 전문을 주고, 그와 별개로 무엇을 왜 고쳤는지 짧게 정리한다. 문장을 하나하나
대조하는 표는 만들지 않는다. 고친 유형별로 묶어 몇 줄이면 충분하다.

원문이 이미 괜찮으면 고치지 않았다고 말한다. 손댈 곳을 찾아내려고 멀쩡한 문장을
바꾸면 글쓴이의 목소리만 옅어진다.

## Common Mistakes

| 실수 | 왜 문제인가 |
|---|---|
| 어미를 일괄 통일 | 원문 말투가 사라져 다른 사람 글이 된다 |
| 문장을 더 매끄럽게 만들려고 전면 재작성 | AI 가 쓴 티가 가장 크게 나는 지점이다 |
| 외래어를 한국어로 치환 | 실무에서 쓰는 말이 어색한 번역어로 바뀐다 |
| 고칠 곳이 없는데 억지로 수정 | 개선이 아니라 손실이다 |
| 수정 내역을 문장 단위 표로 나열 | 읽는 사람이 확인해야 할 양만 늘어난다 |
